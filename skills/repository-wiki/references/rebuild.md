# `/wiki rebuild`

Reconstruct a proposed wiki from registered sources when the schema or accumulated context is no longer trustworthy.

1. Require explicit confirmation before beginning because rebuilds are expensive and broad.
2. Inspect uncommitted changes affecting the canonical wiki, manifest, and registered sources. Abort unless the user explicitly approves how those changes will be included and preserved. Record the initial status, existence, and unfiltered content identities only for those protected project paths. Exclude the configured rebuild staging path and other workflow-owned staging artifacts from this snapshot and every drift comparison.
3. Build the replacement under the configured rebuild staging path without modifying the canonical wiki or manifest.
4. Before processing evidence, validate the current manifest and verify every registered source using the shared source path-safety rules, existence state, and recorded unfiltered identity. Stop and report every missing source, unsafe path, identity mismatch, or unresolved tombstone; never generate a replacement manifest from changed bytes or claim source completeness.
5. Process verified registered sources in chronological or dependency-aware order.
6. Generate a replacement manifest alongside the proposed wiki using the normative manifest shape while preserving each verified source identity.
7. Run the equivalent of `/wiki check` against the proposal.
8. Compare only the protected canonical wiki, manifest, and registered-source paths with the initial snapshot; ignore the configured rebuild staging path and other workflow-owned staging artifacts. If a protected path drifted, stop and refresh the proposal and review. Otherwise, create an exact create, update, and delete inventory. From that complete target set, record a final baseline for every target: its unfiltered content identity when present or an explicit `absent` sentinel when missing. Preserve the current bytes of every present target in the rebuild staging area and record the exact relative path and unfiltered identity of every preserved rollback copy; record an `absent` rollback sentinel for missing targets. After the proposal is final, also record the exact relative path set and unfiltered content identity of every staged replacement file and every staging artifact that controls the target or deletion inventory, then present that exact inventory and diff for approval.
9. Immediately before replacement, reverify every registered source against the unchanged manifest, apply the shared write-path safety checks to every target, and verify both existence and content of every target against the final target baseline, including paths recorded as `absent`. Also verify that the staged path set, replacement identities, and controlling inventory artifacts exactly match the approved staging snapshot; additions, removals, renames, or content changes are drift. Abort and regenerate the inventory and diff if the sources, manifest, targets, or staging area drifted. Replace current files only after a second explicit approval against all unchanged snapshots. Rely on Git for committed history; retain the staged baselines until replacement and validation succeed.
10. Record replacement identities or `absent` sentinels for deleted paths, then run `/wiki check` again. If validation fails, restore the preserved baseline only after repeating the shared write-path safety checks for every rollback target, verifying every target still matches the replacement state, and verifying the exact rollback-copy path set, identities, and `absent` sentinels still match the snapshot from step 8. Restore present baselines from verified copies; delete an operation-created target with an `absent` rollback sentinel only when it still matches the replacement identity and its parent remains safe. If a target or rollback copy is unsafe or drifted after replacement, do not overwrite or delete the target; preserve the staging data and report the paths requiring manual reconciliation.

Completion condition: the proposed replacement and manifest are source-complete, checked, diffable, unchanged since approval, and have not replaced canonical context or concurrently created paths without approval.
